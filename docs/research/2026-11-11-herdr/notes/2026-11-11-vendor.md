## Documentation at herdr.dev, version 0.9.5

Read through `https://herdr.dev/llms.txt` ("Current stable release: 0.9.5"),
which links each page's source at the `v0.9.5` tag in the repository
(`docs/next/website/src/content/docs/*.mdx`). Read in full: index, Agents,
Concepts, Quick start, Install, Session state and restore, Persistence and
remote access, Connecting machines, How to work with Herdr, Integrations,
Agent automation, Keyboard, Troubleshooting; Socket API in part (overview
and socket paths). The human-readable pages are at
`https://herdr.dev/tui/docs/…`.

What they say, in brief:

- **Agents recognised** (Agents page): supported by Herdr, with an
  integration: Claude Code, Codex, GitHub Copilot CLI, Cursor Agent CLI,
  OpenCode, Pi, OMP, Droid, Devin CLI, Kimi Code CLI, Kilo Code CLI, Hermes
  Agent, Qoder CLI, Qwen Code, Letta Code, MastraCode, Grok CLI, Antigravity
  CLI; state only, no integration: Amp, Kiro CLI, Maki, Gemini CLI ("less
  tested"), Cline ("less tested"). Agents that report their own state: Command
  Code, Crush, Kiro CLI, Muse Code, Prime Agent. "Other agents still run
  normally in Herdr panes. They just show up as plain terminals." The
  installed binary's `herdr agent start --kind` accepts 24 kinds: pi,
  claude, codex, gemini, cursor, devin, agy, cline, omp, mastracode,
  opencode, copilot, kimi, kiro, droid, amp, grok, hermes, kilo, qodercli,
  qwen, letta, maki, muse.
- **How state is detected** (Agents, "How status works"): Herdr "finds the
  agent's process in each pane and reads the live bottom of the pane, not
  the part you scrolled to. Rules in a detection manifest decide whether
  that screen means idle, working, or blocked. When an integration also
  reports state, Herdr uses those reports instead of reading the screen."
  For Claude Code and Codex, the integrations report only session identity;
  state comes from the screen (Integrations page).
- **Blocked is strict** (Agents, "Blocked state"): marked only when the
  screen "matches known visible approval, question, or permission UI. If no
  manifest rule matches for a known agent, Herdr falls back to idle"; "idle
  status is not authorization to approve an action".
- **States** (Concepts): blocked, working, done ("finished and you have not
  looked at it yet"), idle ("finished or waiting and has been seen"),
  unknown. Each client tracks which completions it has displayed.
- **Detection manifests update from the network** (Agents): "Herdr also
  checks herdr.dev for remote manifest updates and applies valid per-agent
  rule updates automatically". Off with `[update] manifest_check = false`.
- **Session restore** (Session state and restore): detach keeps processes
  running; after a server restart "the original pane processes are gone"
  and Herdr restores layout and directories; conversations resume only for
  agents whose integration is installed (Claude Code integration v6+,
  `claude --resume <id>`; Codex v5+, `codex resume <id>`). Screen history
  replay is off by default "because pane output can include secrets".
- **Integrations write into the agent's own configuration**: Claude Code's
  writes `hooks/herdr-agent-state.sh` and edits `settings.json` in
  `~/.claude`; Codex's writes a hook script, edits `hooks.json` and sets
  `[features] hooks = true` in `config.toml` (Integrations page).
- **Remote use** (How to work, Persistence and remote, Connecting machines):
  three paths. `ssh` to the machine and run `herdr` there (like tmux, also
  from a phone SSH client); `herdr --remote <host>` (remote server, local
  UI, local keybindings, local clipboard images bridged); `herdr machine
  add` for several saved SSH machines in one window. Remote hosts: Linux and
  macOS (x86_64, aarch64), Windows x86_64. If the remote host has no
  compatible `herdr`, interactive runs offer to install one in
  `~/.local/bin`.
- **Named sessions** (Persistence): `herdr session list|attach|stop|delete`;
  each has its own panes, sockets and state but shares the global config.
- **Worktrees**: `herdr worktree create|open|remove|list` (CLI help).
- **Automation** (Agent automation, `herdr --skill`): `workspace`, `tab`,
  `pane` and `agent` subcommands print JSON; `agent start`, `agent prompt
  --wait`, `agent wait --until`, `agent read`, `agent send-keys`, `agent
  explain`.
