## Running it from a script

- "By default, `codex exec` runs in a read-only sandbox." "Allow edits:
  `codex exec --sandbox workspace-write "<task>"`". "`--full-auto` is no
  longer supported."
- "Use `--ignore-user-config` when you need a run that doesn't load
  `$CODEX_HOME/config.toml`".
- `--json` streams events; `-o` writes the last message to a file.
- `codex exec resume <SESSION_ID> [PROMPT]` continues a session (from
  `--help`); it has no `-s` flag, so the sandbox is set with
  `-c sandbox_mode="workspace-write"`.
- `-c key=value` "Override a configuration value that would otherwise be
  loaded from `~/.codex/config.toml`"; `--disable <FEATURE>` is "Equivalent to
  `-c features.<name>=false`".

## Switching off MCP servers, plugins and connectors (config reference)

- `mcp_servers.<id>.enabled`: "Disable an MCP server without removing its
  configuration."
- `plugins.<plugin>.enabled`: "Enable or disable a local-marketplace plugin".
- `plugins.<plugin>.mcp_servers.<server>.enabled` (listed, no description).
- `plugins._default.enabled`: "Set the default activation state for
  installed plugins."
- `features.apps`: "Enable app (connector) integrations (stable; on by
  default)."
- `features.memories`: "Enable Memories (off by default)."
- `features.plugins`: "Pin plugin availability on or off for managed users."
- `web_search`: default `"cached"`, which "uses an OpenAI-maintained index
  without external web access". Left at its default in the tests.

What actually worked is in test.md: only `--disable plugins` removed a
bundled plugin's MCP server.

## Prompting (vendor advice)

- The four parts: "**Goal**", "**Context**", "**Output**", "**Boundaries**".
  "A short prompt is often enough." "Use only the parts that help."
- Boundaries, as examples: "Use only the supplied sources. Flag missing
  information instead of guessing." "Prepare the message as a draft. Don't
  send it." "Focus on the one or two boundaries that matter most."
- Checking: "For important work, ask ChatGPT for a final check, such as
  confirming every action item has an owner and due date or flagging
  information it couldn't verify. Then review the result yourself before you
  use or share it."
- Planning: "Ask for a plan when the approach matters. Require your approval
  before ChatGPT sends, publishes, or changes information other people rely
  on." For Codex: "enter `/plan` in the app composer when you want Codex to
  investigate and propose an approach before editing."
- Personal preferences: "Put preferences that should apply across chats in
  **Settings > Personalization** as custom instructions. Keep details that
  matter only to the current chat in the prompt."

## Sandbox

"The sandbox defines technical boundaries. The approval policy decides when
the agent must stop and ask before crossing them." "The sandbox applies to
spawned commands, not just to built-in file operations."

## Slash commands worth a beginner's time

`/plan` "Toggle plan mode for multi-step planning"; `/init` "Generate an
`AGENTS.md` scaffold"; `/memories`; `/model`; `/reasoning`; `/status` "Show the
chat ID, context usage, and rate limits"; `/usage`; `/mcp` "Open MCP status to
view connected servers".
