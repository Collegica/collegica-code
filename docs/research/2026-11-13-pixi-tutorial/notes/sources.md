# Sources read, and what each claim rests on

All read on 13 November 2026. pixi's documentation moved from `pixi.sh` to
`pixi.prefix.dev` (`https://pixi.sh` now redirects there); the install script
URLs still use `pixi.sh`.

## pixi: documentation

| Page | Used for |
|---|---|
| [Installation](https://pixi.prefix.dev/latest/installation/) | Install commands: `curl -fsSL https://pixi.sh/install.sh \| sh` (the draft piped to `bash`); Windows `powershell -ExecutionPolicy Bypass -c "irm -useb https://pixi.sh/install.ps1 \| iex"`, `winget install prefix-dev.pixi`, Scoop, MSI; `brew install pixi`. Binary in `~/.pixi/bin`, script edits the shell profile (`PIXI_NO_PATH_UPDATE` opts out), sends one anonymous install ping (`PIXI_NO_TELEMETRY=1` opts out). Update with `pixi self-update` or `brew upgrade pixi`. |
| [Python tutorial](https://pixi.prefix.dev/latest/python/tutorial/) | `pixi init --format pyproject`; `pixi add --pypi`; a feature-only task picks its environment by itself ("`pixi run test` switched to the `test` environment"). |
| [Manifest reference](https://pixi.prefix.dev/latest/reference/pixi_manifest/) (first 100,000 of 125,000 characters) | `[workspace]` fields; "When using pypi-dependencies, python is needed to resolve pypi dependencies"; per-dependency channel as `{ version = …, channel = "pytorch" }`; task fields `cmd`, `depends-on`, `env`, `cwd`, `inputs`, `outputs`, `default-environment`. |
| [Advanced tasks](https://pixi.prefix.dev/latest/workspace/advanced_tasks/) | `description`; `depends-on` (hyphen; the underscore form is not shown anywhere); caching: skipped only if packages, inputs, outputs and command are unchanged; "We compute fingerprints of all the files selected by the globs". |
| [Multi environment](https://pixi.prefix.dev/latest/workspace/multi_environment/) | `[feature.<name>.dependencies]`, `[feature.<name>.tasks]`, `[environments]` list and table forms, `solve-group`, `no-default-feature`; the default feature is included implicitly; `pixi run -e`. |
| [Lock file](https://pixi.prefix.dev/latest/workspace/lock_file/) | One lockfile for every environment and platform; regenerated by `install`, `run`, `add`, `remove`; `--locked` vs `--frozen`; commit it (with a carve-out for libraries). Says nothing about merge conflicts. |
| [Conda and PyPI](https://pixi.prefix.dev/latest/concepts/conda_pypi/) | Conda solved first, then PyPI "with the constraints of the already resolved conda dependencies"; conda→PyPI name mapping (numpy example); conda wins duplicates; PyPI side uses uv as a library ("Pixi doesn't install `uv` (the tool) itself"). |
| [pyproject.toml](https://pixi.prefix.dev/latest/python/pyproject_toml/) | `[tool.pixi.*]`; `[project.dependencies]` become PyPI dependencies; `requires-python` becomes the conda `python`; recommended for Python packages, `pixi.toml` for other projects. |
| [Switching from Poetry](https://pixi.prefix.dev/latest/switching_from/poetry/) | Command table (`poetry new` → `pixi init`, `poetry add` → `pixi add` / `pixi add --pypi`, …); building and publishing: "We've yet to implement package building and publishing"; don't run Poetry inside a pixi environment. |
| [FAQ](https://pixi.prefix.dev/latest/misc/FAQ/) | Package building marked 🚧. Nothing on pip or merge conflicts. |
| [pixi global](https://pixi.prefix.dev/latest/global_tools/introduction/) | `pixi global install <pkg>`: one isolated environment per tool, exposed on `PATH`, recorded in a global manifest. Mentioned in one line only; not run (it would change the machine's global setup). |
| [CLI: `pixi add`](https://pixi.prefix.dev/latest/reference/cli/pixi/add/) | No `--channel` option (the draft's `pixi add gdal --channel conda-forge` fails, confirmed in the test); `--feature`, `--platform`, `--git`, `--pypi "pkg @ git+https://…"`. |

## pixi: release notes

`gh release view` on [prefix-dev/pixi](https://github.com/prefix-dev/pixi/releases),
v0.78.0 to v0.84.2. (The `CHANGELOG.md` page on GitHub did not render for the
fetch tool; the release bodies are the same text.)

| Release | Date | Relevant |
|---|---|---|
| 0.78.0 | 28 Aug 2026 | The version tested. `pixi add --path`; manifest writes platform names. |
| 0.79.0 | 3 Sep 2026 | `pixi workspace dependencies add`; `pixi install --script`. |
| 0.80.0 | 7 Sep 2026 | Experimental `conda-script`. |
| 0.81.0 | 15 Sep 2026 | `pixi run --script` from URLs. |
| 0.82.0 | 14 Oct 2026 | `PIXI_WORKSPACE_*` variables, `PIXI_PROJECT_*` now legacy; `exclude-newer` for `pixi global`. |
| **0.82.1** | 20 Oct 2026 | **Security release** (patched TLS certificate dependencies after a certificate-authority compromise): "All users are encouraged to upgrade to this version immediately." Also: docs fixed to say "[project] is the deprecated alias for [workspace]". |
| 0.83.0 | 22 Oct 2026 | Minor. |
| 0.84.0 | 2 Nov 2026 | `exclude-newer` redesigned; config parse errors now fatal (breaking); lockfiles from older versions "may need to have hashes updated by `pixi lock`". Tested: the 0.78.0 lockfile here did not. |
| 0.84.1 / 0.84.2 | 4 / 10 Nov 2026 | Minor; 0.84.2 is current. |

**Consequence for the article:** the tested 0.78.0 predates a security
release. The article tells readers to install the current version and notes
that the walkthrough was run on 0.78.0 and repeated on 0.84.2 (Linux).
